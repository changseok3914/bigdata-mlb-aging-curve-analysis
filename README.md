# MLB 선수 노화 곡선 분석 및 다음 시즌 성과 예측

## 1. 프로젝트 개요

본 프로젝트는 MLB 선수들의 시즌별 성적 데이터를 수집하여, 나이에 따른 성적 변화 패턴을 분석하고 다음 시즌 성과를 예측하는 빅데이터 처리·분석 시스템을 구현하는 것을 목표로 한다.

야구 선수의 성적은 단순히 실력만으로 결정되지 않고, 나이, 경기 출장 수, 포지션, 전년도 성적, 투수/타자 유형 등에 따라 변화한다. 특히 선수의 전성기와 하락 시점을 파악하는 것은 구단의 선수 평가, 계약, 육성 전략에서 중요한 의미를 가진다.

본 프로젝트에서는 MLB 공개 데이터를 기반으로 선수의 나이와 성적 변화 사이의 관계를 분석하고, Spark와 Hive를 활용하여 대용량 야구 데이터를 처리한 뒤 선수 노화 패턴을 시각화하고자 한다.

## 2. 문제 정의

### 2.1 풀고자 하는 문제

본 프로젝트에서 풀고자 하는 핵심 문제는 다음과 같다.

> MLB 선수의 나이에 따른 성적 변화는 어떤 패턴을 보이며, 과거 성적과 나이를 이용해 다음 시즌 성과를 예측할 수 있는가?

이를 위해 다음과 같은 세부 분석 질문을 설정한다.

1. MLB 타자의 주요 성적 지표는 나이에 따라 어떻게 변화하는가?
2. MLB 투수의 주요 성적 지표는 나이에 따라 어떻게 변화하는가?
3. 선수의 전년도 성적과 나이를 이용해 다음 시즌 성과를 예측할 수 있는가?
4. 타자와 투수의 노화 패턴은 서로 다르게 나타나는가?
5. 특정 나이 구간에서 성적 하락 폭이 크게 나타나는가?

### 2.2 사용할 데이터

본 프로젝트에서는 MLB 공개 데이터를 사용한다.

사용 예정 데이터는 다음과 같다.

1. MLB 시즌별 선수 성적 데이터
   - 타자: 타율, 출루율, 장타율, OPS, 홈런, 타점, 도루, 삼진, 볼넷 등
   - 투수: 평균자책점, 이닝, 탈삼진, 볼넷, 피홈런, WHIP 등

2. MLB 선수 기본 정보 데이터
   - 선수 ID
   - 선수 이름
   - 생년월일 또는 나이
   - 포지션
   - 투타 유형

3. Statcast 데이터
   - 투구 단위 또는 타구 단위 데이터
   - 구속, 타구 속도, 발사각, 이벤트 결과 등

데이터 출처는 pybaseball, Baseball Savant, Lahman Baseball Database 등을 활용할 예정이다.

데이터는 단일 파일 하나만 사용하는 것이 아니라, 여러 시즌 또는 날짜 단위로 나누어 수집한 뒤 HDFS에 적재한다. 최종적으로 누적 100MB 이상의 데이터를 확보하는 것을 목표로 한다.

## 3. 기술 스택

본 프로젝트에서 사용할 기술 스택은 다음과 같다.

| 구분 | 사용 도구 | 역할 |
|---|---|---|
| 데이터 수집 | Python, pybaseball | MLB 선수 성적 및 Statcast 데이터 수집 |
| 저장소 | HDFS | 수집한 원천 데이터를 Hadoop 분산 파일 시스템에 저장 |
| 전처리 | Apache Spark | 결측치 처리, 타입 변환, 선수별/시즌별 데이터 정리 |
| 분석 | Spark SQL, HiveQL | 나이 구간별 성적 집계 및 비교 분석 |
| 예측 모델 | Spark MLlib | 다음 시즌 성과 예측 모델 구현 |
| 테이블 관리 | Apache Hive | 전처리된 데이터를 Hive 테이블로 관리 |
| 시각화 | Python, Matplotlib, Plotly | 노화 곡선 및 예측 결과 시각화 |
| 자동화 | Bash Script | 데이터 수집부터 분석까지 실행 흐름 자동화 |
| 버전 관리 | Git, GitHub | 코드 및 산출물 관리 |

핵심 데이터 처리와 분석은 Pandas가 아니라 Spark와 Hive를 중심으로 수행한다. Pandas는 결과 확인 또는 시각화 보조 용도로만 사용한다.

## 4. 구현 계획

### 4.1 데이터 수집

Python 스크립트를 작성하여 MLB 공개 데이터를 수집한다.

예상 수집 방식은 다음과 같다.

1. 분석 기간 설정
   - 예: 2015년~2025년 MLB 시즌 데이터
2. 연도별 타자/투수 성적 데이터 수집
3. 선수 기본 정보 데이터 수집
4. Statcast 데이터 수집
5. CSV 파일로 로컬 저장
6. 수집된 데이터의 총 용량이 100MB 이상인지 확인

예상 디렉토리 구조는 다음과 같다.

```text
data/
  raw/
    batting_2015.csv
    batting_2016.csv
    pitching_2015.csv
    pitching_2016.csv
    statcast_2024_04.csv
    statcast_2024_05.csv
